# Доска задач и самоизлечение — замысел, кейсы, сложные случаи

Черновик, кода нет. Реализация — только после «ок» человека. Кадры доски сняты стендом
(scratchpad вкладки, `board/out/frame-1..6.png`): рабочая зона, своя доска, доска из
трекера, карточка задачи, «Отложить», новая доска. Кадров ретро пока нет.

## Зачем

Сейчас главная единица сворма — вкладка, то есть процесс. Задача живёт в ней случайно: одна
вкладка за три дня проходит через шесть задач (досье этой вкладки — шесть разделов «Задача
(новая)»), досье пухнет, план затирается, дайджест описывает только последнюю. Отложить
задачу на неделю негде: либо держать вкладку открытой, либо закрыть и искать в «Прошлых
разговорах».

Доска переворачивает это: **главное — задача, вкладка — место, где её сейчас делают.**
Вторая половина — **самоизлечение**: агент, который зовёт человека зря (или не зовёт, когда
надо), замечается, и правила работы поправляются сами — но с согласия человека.

Это действительно складывается в каркас вокруг агентов: задача → агент → проверка → выводы.
Три звена из четырёх уже есть (досье, файл работы, вопросы, сон, история, прораб, ночь);
доска связывает их в цикл, ретро замыкает его.

# Часть 1. Доска

## Понятия

| Понятие | Что это | На что опирается из того, что есть |
|---|---|---|
| **Доска** | Набор задач с одним источником и своими правилами | новое |
| **Задача** | Бриф, правила, план, вопросы, история сессий | досье, файл работы, questions.md, саммари |
| **Сессия** | Один разговор агента над задачей | вкладка, `--resume`, перезапуск |
| **Источник** | Откуда задачи приходят: своя доска, Яндекс Трекер, GitHub | новое |

Задача переживает сессии: перезапуск по контексту, падение, неделя в «Ожидании». Claude
хранит разговор 30 дней, задача — сколько нужно: протух разговор — задача поднимается свежей
сессией по досье и файлу работы (тот же механизм, что у перезапуска).

## Колонки

| Колонка | Агент | Где видна | Кто переводит сюда |
|---|---|---|---|
| **Входящие** (у трекера — «Из трекера») | не запущен | только доска, счётчик внизу списка | человек, Телеграм `/task`, сверка с трекером |
| **В работе** | живой или спит | список вкладок, как сейчас | «В работу», возврат из Ожидания |
| **На проверке** | спит | список вкладок, сиреневая карточка | агент меткой `[swarm:готово]` |
| **Ожидание** | закрыт | счётчик внизу списка | человек («Отложить…») |
| **Готово** | закрыт | доска, поиск | **только человек** («Принять») |

Закрывает задачу только человек (решение 16.11). Агент может только сдать на проверку.
«Вернуть…» с проверки — с замечанием, оно ложится в досье как правило задачи, и задача
возвращается в «В работе».

## Несколько досок

Досок сколько угодно (решение 16.11): «Svarmo», «Housebook · Трекер», «Личное». Переключатель
сверху списка вкладок. У доски есть папка (или несколько) — где агент работает над её
задачами. Список вкладок слева показывает «В работе» текущей доски; вкладки других досок, которым
нужен человек (бирюзовая, сиреневая), видны счётчиком на переключателе — иначе вопрос с
соседней доски потеряется.

Вкладка «по-быстрому» (спросить и закрыть) не требует оформления: она попадает на доску
своей папки сама, имя — от агента, как сейчас. Если у папки нет доски — на доску «Без доски»,
которая в переключателе не показывается, пока пуста.

## Источники задач

### Своя доска (трекера нет)

Сворм — источник. Задачи создаются кнопкой «+ задача», в Телеграме `/task текст`, голосом.
Хранятся в папке настроек сворма (`boards/<id>/`), рядом с досье, не в репозитории — по той же
причине, что досье: не уехать в чужой коммит.

### Внешний трекер — задача расписана хорошо

Задачу **не переоформляем**. Бриф = текст задачи из трекера + ссылка + вложения. Правка
текста в трекере подтягивается при сверке; если агент уже работает — ему приходит строка
«в HB-1423 поменялось описание», а не молчаливая подмена брифа. В досье у нас лежит только
своё: правила человека, план агента, заметки.

### Внешний трекер — описано скупо

Метка «описано скупо» ставится при сверке (короткий текст, нет критериев готовности).
Агент на старте сначала уточняет у человека — это законный вызов, ретро его не считает пустым.
Уточнения ложатся в досье задачи, **не в трекер**: трекер видят коллеги, писать туда — наружу.

### Что пишем в трекер

По умолчанию — только статус и только кнопками человека:

| Кнопка в сворме | Яндекс Трекер | GitHub |
|---|---|---|
| В работу | «В работе» | issue: назначить на себя, метка `in progress` |
| сдана на проверку | «На ревью» (если есть в очереди) | открыт PR со ссылкой на issue |
| Принять | «Решён» | PR смёрджен, issue закрыт |
| Отложить | без изменений | без изменений |

Агент сам в трекер не пишет. Комментарии с ходом работы — отдельная настройка доски, по
умолчанию выключена (открытый вопрос, см. в конце).

### Сверка

Сворм сам опрашивает трекер (раз в несколько минут, когда приложение открыто) по фильтру
доски. Задача ушла из фильтра (переназначили, закрыли в трекере) — карточка не исчезает
молча: она получает метку «ушла из трекера» и ждёт решения человека. Если по ней идёт работа,
агенту приходит строка об этом.

## Ожидание

«Отложить…» — причина (видна на карточке) и когда вернуть:

- **сам верну**;
- **когда закроется задача X** (после её «Принять»);
- **когда ответят в трекере** (новый комментарий в задаче) — только у задач из трекера;
- **в день и время**.

Это та же запись «[до: событие]», что в досье, только про задачу целиком. Отложить — значит
усыпить агента (проверки сна: идут подагенты, сборка или будильник — сначала спросить) и
убрать карточку из списка. Вернулась сама — карточка встаёт в «В работе» зелёной (ждёт
задания) и агент НЕ стартует сам, если у вкладки нет мандата ночи: вернуть в список ≠ начать
работу без человека. С мандатом — стартует с досье и строкой «вернулась из ожидания: <событие>».

## Ночь и прораб

- Ночному режиму можно отдать не только открытые вкладки, но и входящие с меткой «можно без
  меня». Утром — в «На проверке» (или в «В работе», если застряла).
- Прораб берёт задачи с доски и раздаёт исполнителям, а не придумывает их сам. Исполнитель
  сдаёт — задача идёт на проверку человеку, прораб её не закрывает.

## Телеграм — минимум

Телеграм — способ потыкать задачу в такси, не второй интерфейс доски (слово человека 16.11).
Туда идёт только:

- `/task текст` — во «Входящие» текущей доски (или `/task @доска текст`);
- уведомление «сдана на проверку» с одной строкой итога — **без кнопок** «Принять/Вернуть»:
  принять работу, не глядя на неё, нельзя, а глядеть с телефона неудобно;
- ответы на вопросы агентов — как сейчас.

Не идёт: доска целиком, перетаскивание, ретро, отметки «можно было без меня» под каждым
сообщением. Ретро в Телеграм — одна строка раз в неделю: «Ретро готово: 3 предложения, на
компе».

# Часть 2. Самоизлечение

## Цель

Агент зовёт человека, только когда без него нельзя, и зовёт всегда, когда нельзя без него.
Обе ошибки замечаются и чинятся правилами. Метрика успеха — **пустых вызовов меньше, возвратов
с проверки не больше**. Лечить только первое — значит вылечить агента до немоты.

## Уровни правил

| Уровень | Где живёт | Пример | Кто видит |
|---|---|---|---|
| **Глобальный** | папка настроек сворма, `rules/global.md` | «отчитывайся продуктово, без внутренностей» | все агенты всех проектов |
| **Проект** | папка настроек сворма, `rules/projects/<папка>.md`; разрешения — `.claude/settings.local.json` проекта | «коммитить свои правки без вопроса», «прогон тестов разрешён» | все задачи в этой папке |
| **Доска** | `boards/<id>/rules.md` | «в трекер не писать», «мелкие правки без вопросов» | задачи доски |
| **Задача** | досье, раздел «Правила задачи» | «не трогать модуль платежей» | одна задача |

Старшинство — узкое главнее широкого: задача > доска > проект > глобальный. Противоречие
между уровнями ретро не прячет, а выносит отдельным пунктом («на проекте „коммитить без
вопроса“, на доске Housebook „коммиты только по слову“ — так и задумано?»).

Чужой `CLAUDE.md` в репозитории сворм **молча не правит**: он общий с командой и уезжает в
коммиты. Правило уровня «проект» можно перенести туда отдельной кнопкой «Перенести в
CLAUDE.md» — по явному действию человека.

Доставка агенту: глобальные + проектные + досочные правила подаются при старте сессии тем же
путём, что правило меток (`--append-system-prompt`) или текстом хука старта; правила задачи
уже доставляет досье. Объём ограничен: по 15 правил на уровень, дальше ретро обязано
предложить слить или убрать.

## Сырьё: каждый вызов — событие

Сворм уже видит каждый вызов человека: вопрос (тег, AskUserQuestion, questions.md), запрос
разрешения, сдачу на проверку. Каждый пишется в журнал задачи (`calls.jsonl`) с исходом:

| Сигнал | Откуда | Вес |
|---|---|---|
| **Отметка «можно было без меня»** | человек, кнопкой | решающий |
| Ответ без содержания: «да», «го», «ок», «сам реши», «как считаешь» | текст ответа | средний |
| Выбран вариант, который агент сам пометил «(Recommended)» | AskUserQuestion | средний |
| Разрешение на одну и ту же команду дали N раз из N | запросы разрешений | средний |
| Раздражение: «зачем спрашиваешь», «я же говорил», «опять» | текст ответа | высокий |
| **Обратное:** «Вернуть…» с проверки | доска | высокий |
| **Обратное:** «надо было спросить», откат сделанного | текст, git | высокий |
| **Обратное:** отказ в разрешении | запросы разрешений | средний |

Пустой ответ сам по себе ничего не доказывает: человек мог сказать «да», потому что агент
спросил правильно. Поэтому правило предлагается только на серии (от 5 одинаковых исходов без
единого несогласия), а одиночная отметка человека весит как серия.

## Как помечать — удобно и без лишних кликов

Главное — **почти ничего не помечать руками**: косвенные сигналы собираются сами. Ручная
отметка — для случаев, когда хочется сказать громко.

- **В панели «Вопросы»** у каждого отвеченного вопроса агента — тихая кнопка «↯ можно было
  без меня», видна при наведении. Второй клик снимает.
- **На карточке задачи на проверке** при «Вернуть…» — замечание пишется словами; ретро
  считает его обратным сигналом само, отдельной отметки не нужно.
- **Словом в ответе.** «сам реши», «не спрашивай такое» прямо в ответе агенту — уже сигнал
  высокого веса, кнопка не нужна. Это же единственный способ в Телеграме.
- **Агенту сразу.** Сильный сигнал (раздражение, «не спрашивай такое») не ждёт ретро: агенту
  приходит строка «человек считает такой вопрос лишним — запиши правило задачи», и до конца
  задачи он так больше не делает. Ретро потом решает, поднимать ли правило выше.

## Ретро

### Маленькое — при «Принять»

Задача закрыта. Если в журнале вызовов нет сигналов — ретро не запускается вовсе (молчит и не
тратит подписку). Если есть — дешёвая модель читает журнал, вопросы, замечания возвратов и
приносит 0–3 предложения. Они появляются в карточке принятой задачи и в общем списке
предложений доски; ничего не всплывает поверх работы.

### Недельное — по всем доскам

Раз в неделю (понедельник утром, или когда человек откроет приложение после этого) — сводка:

- вызовов на задачу, из них пустых, возвратов с проверки, время ожидания человека — по
  каждой доске, рядом прошлая неделя;
- предложения, которые видны только на многих задачах (подъём правила с уровня задачи на
  проект или глобальный);
- уборка: правила, которые не срабатывали месяц, дубли, противоречия.

### Предложение

Каждое предложение — одна правка с уровнем и доказательством:

> **На «коммитить?» вы 6 раз ответили «да», ни разу «нет»**
> Правило: коммитить свои правки без вопроса, добавляя файлы поимённо.
> Уровень: [проект claude-swarm-lite ⌄] · 6 задач, последняя «Панель вопросов»
> [Принять] [Отклонить] [Поправить текст]

Уровень предлагает ретро по разбросу доказательств: всё в одной задаче → задача; в разных
задачах одной папки → проект; одной доски, но разных папок → доска; в разных проектах →
глобальный. Человек меняет уровень выпадашкой.

Отклонённое запоминается вместе с доказательствами и не предлагается снова, пока не накопится
вдвое больше новых.

### Проверка, что лечение сработало

У принятого правила есть дата. Через неделю ретро сравнивает до и после по задачам, где правило
действовало: вызовов этого рода меньше и возвратов не больше — правило остаётся молча. Возвратов
стало больше — предложение «откатить правило» с теми возвратами в доказательствах.

## Что ретро не трогает никогда

Необратимое и наружное зовёт человека при любой статистике: релиз, пуш в общий репозиторий,
удаление данных, запись во внешние сервисы (трекер, почта, чужие чаты), трата денег. Такие
предложения ретро не формирует вовсе, даже если человек сто раз сказал «да». Это совпадает с
правилом проекта «релиз — только по прямому разрешению».

# Часть 3. Кейсы

**1. Обычный день, своя доска.** Утром во «Входящих» три задачи, одна пришла вчера из
Телеграма. Человек жмёт «В работу» на двух — открываются две вкладки с брифами в досье. Одна к
обеду сдана: сиреневая карточка. Человек смотрит дифф, жмёт «Принять» — задача в «Готово»,
маленькое ретро молчит (сигналов нет).

**2. Задача из трекера, хорошо описана.** HB-1423 с ТЗ и критериями. «В работу» — вкладка в
папке housebook-api, бриф — текст задачи, в трекере статус «В работе». Агент сдаёт с PR —
«На ревью». Человек принимает — «Решён».

**3. Задача из трекера, одна строка.** «Падает импорт квартир». Агент первым ходом спрашивает,
на каком файле и с какой ошибкой. Ответ — в досье, не в трекер. Этот вызов ретро не считает
пустым: у задачи метка «описано скупо».

**4. Отложить до ответа коллеги.** Задача ждёт решения от бухгалтерии. «Отложить» → «когда
ответят в трекере». Через два дня в задаче комментарий — карточка сама возвращается в «В
работе» зелёной, с причиной «вернулась: ответ в HB-1377».

**5. Агент зовёт по пустякам.** Неделю агент спрашивает «закоммитить?», человек каждый раз
«да». Недельное ретро: «6 из 6 — коммитить без вопроса? уровень: проект». Принято. Следующая
неделя: вопросов о коммитах ноль, возвратов столько же — правило остаётся.

**6. Агент не позвал, когда надо было.** Агент сам выбрал формат выгрузки, человек вернул
задачу: «формат согласуют с бухгалтерией, надо было спросить». Возврат — сигнал высокого веса.
Маленькое ретро: «спрашивать до выбора формата обмена с внешними системами? уровень: доска».

**7. В такси.** Пришла мысль — `/task поправить формат дат в отчётах` в Телеграм, задача во
«Входящих». Агент другой задачи спрашивает — ответ «сам реши» прямо в чат; это и ответ, и
сигнал. Больше в Телеграме ничего делать не нужно.

**8. Ночью.** Три входящих с «можно без меня» отданы ночи. Утром две на проверке, одна в «В
работе» с вопросом. В ретро ночные вызовы считаются отдельно: ночью агент и так не зовёт.

# Часть 4. Сложные случаи

**Вылечили до немоты.** Правила копятся, агент перестаёт спрашивать, начинает ошибаться.
Защита: метрика возвратов рядом с метрикой вызовов, автоматическое предложение откатить правило
при росте возвратов, необратимые действия вне ретро.

**«Да» от усталости.** Человек отвечает «да» не глядя, потому что устал. Серия «да» тогда
выглядит как лишний вопрос, хотя вопрос был нужен. Защита: правило применяется только после
явного «Принять» в ретро — в момент, когда человек думает именно о правиле.

**Одно правило — разные проекты.** «Коммитить без вопроса» хорошо в своём проекте и плохо в
рабочем, где коммиты ревьюят. Поэтому ретро предлагает уровень по разбросу доказательств, а не
сразу глобальный; подъём на глобальный — только если серия есть в нескольких проектах.

**Противоречие уровней.** Глобальное «коммить сам», проектное «коммиты по слову». Узкое
главнее, ретро показывает противоречие в недельной сводке одним пунктом — вдруг оно случайное.

**Правило из ретро против CLAUDE.md проекта.** CLAUDE.md — общий с командой, его правила
старше наших проектных. Ретро не предлагает правило, противоречащее CLAUDE.md, а показывает
«в CLAUDE.md сказано обратное — поправить там?» без кнопки правки (только открыть файл).

**Правила раздуваются.** Каждое правило — текст в контексте каждой сессии. Лимит по 15 на
уровень, недельная уборка: не срабатывало месяц — предложить убрать; два похожих — слить.

**Прораб и исполнители.** Вопрос исполнителя прорабу — тоже вызов, но не человека. Считается
отдельно: прораб ответил сам — хорошо; прораб переспросил человека — вызов человека от имени
исполнителя, и сигнал идёт обоим.

**Задача сменила доску или папку.** Правила задачи едут с ней, правила доски и проекта — нет:
на новом месте действуют новые. Журнал вызовов остаётся при задаче, ретро относит старые
события к старой доске.

**Задача ушла из трекера посреди работы.** Переназначили на коллегу. Карточка получает метку
«ушла из трекера», агент — строку об этом и останавливается после текущего шага; решает
человек: забрать в свою доску, отложить или закрыть.

**Разговор протух в Ожидании.** Задача пролежала больше 30 дней. «В работу» поднимает свежую
сессию по досье и файлу работы, с пометкой «разговор не сохранился, всё, что знаешь, — в
досье».

**Ретро на пределе подписки.** Ретро — фоновая трата. Если подписка за 80% окна — ретро
откладывается до сброса, недельная сводка выходит без предложений («посчитано, разобрать после
сброса»).

**Кто такой «человек», если вкладок две на разных аккаунтах.** Сигналы относятся к задаче, а
не к аккаунту; правила тоже. Подписка влияет только на то, чем платить за ретро.

**Отметка по ошибке.** «↯» снимается вторым кликом; если ретро уже учло — при следующем
пересчёте она выпадает. Принятое правило снимается в списке правил уровня одной кнопкой.

# Часть 5. Порядок реализации

Каждый этап самостоятелен и полезен без следующих.

1. **Задача как сущность + Ожидание.** Карточка переживает процесс; «Отложить…» с причиной и
   условием возврата; счётчики «Входящие / Ожидание / Готово» внизу списка. На проверке —
   по метке готово, «Принять / Вернуть…» — только человек.
2. **Входящие и своя доска.** «+ задача», `/task` в Телеграме, вид доски по ⌘B, несколько
   досок и переключатель.
3. **Журнал вызовов и отметка «↯».** Сбор сигналов, кнопка в панели «Вопросы», немедленная
   строка агенту при сильном сигнале. Уровни правил и их доставка агенту.
4. **Ретро.** Маленькое при «Принять», недельное, предложения кнопками, проверка через неделю.
5. **Трекеры.** Яндекс Трекер и GitHub: подключение одной кнопкой, сверка, статусы по кнопкам.
